2. RENDERING STRATEGY
================================================================

Route Type          | Rendering  | Why
--------------------|------------|-----
Homepage            | ISR (60s)  | Content changes infrequently, needs speed
About pages         | ISR (300s)  | Static content, rarely changes
Product pages       | ISR (300s)  | Product info stable
Service pages       | ISR (300s)  | Service info stable
Rate pages          | SSR         | Rates change monthly, need fresh data
News articles       | ISR (60s)   | New articles frequently added
Events              | ISR (60s)   | Event updates
Notices             | SSR         | Time-sensitive
Reports             | ISR (3600s) | Annual/quarterly, rarely changes
Gallery             | ISR (300s)  | Album additions infrequent
Downloads           | ISR (3600s) | Static files
FAQ                 | ISR (3600s) | Rarely changes
Careers             | SSR         | Job openings update frequently
EMI Calculator      | Client      | Interactive JS app
Loan Enquiry        | Client      | Form submission
Branch Map          | Client      | Interactive map
Calendar            | Client+SSR  | Calendar nav is interactive
Search              | SSR         | Query-dependent
Contact Form        | Client      | Form submission
CMS /admin/*        | Client      | Dashboard SPA (client-only)

5. DATA FLOW PATTERN
================================================================

Request Flow:
  Browser → Next.js (Edge/Server)
    → ISR/SSR fetches from Hono Worker API
    → Hono Worker queries D1 via Drizzle
    → Returns JSON → Next.js renders HTML
    → Served via Cloudflare Pages

Form Submission Flow:
  Browser → Next.js (Client)
    → POST to Hono Worker API
    → Hono validates with Zod
    → Writes to D1 + optionally R2 (file upload)
    → Sends email via Cloudflare Email Workers
    → Returns success response

CMS Edit Flow:
  Browser → Next.js (Client)
    → Auth.js session check
    → CMS page loads via Hono Worker CMS API
    → Editor makes changes → Autosave to local state
    → Manual Save → PATCH to Hono Worker
    → Creates version snapshot in page_versions
    → Updates page in D1
    → Returns updated page

Media Upload Flow:
  Browser → Next.js (Client)
    → Upload file → Hono Worker receives multipart
    → Uploads to R2 with unique filename
    → Triggers Cloudflare Images for optimization
    → Creates thumbnails + responsive variants
    → Stores metadata in media table
    → Returns URLs

Search Flow:
  Browser → Next.js (Server)
    → GET /api/search?q=term
    → Hono Worker searches FTS5 index
    → Returns ranked results grouped by type
    → Next.js renders SearchResults component
